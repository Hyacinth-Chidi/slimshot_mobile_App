# Text Size — a real font size, separate from scale

**Goal:** A text's letters can be made bigger or smaller with a ruler, the way CapCut's font
size works: the letters grow, the lines re-wrap inside the text's width, the style keeps its
proportions, and the size means the same on every phone. Pinch stays scale.

**Agreed with the user (2026-10-03).** Executed inline by the author on `feat/auto-captions`,
test first.

## Decisions

- **Two controls, as CapCut has them.** *Size* is the letters (a style: constant, re-wraps);
  *scale* is the whole text as an object (the pinch, the corner handle, keyframed zooms).
  Neither is folded into the other.
- **Size is frame-relative.** `TextOverlayModel.fontSize`: the letters' em size in thousandths
  of the frame's **short side** — Size 100 is a tenth of the frame (the caption rule, which
  was a tenth of the width; on the default 9:16 canvas the width is the short side). A size
  then looks the same on any phone. Short side, not width, so a landscape project's text is
  not sized by its long side.
- **Null is the old meaning** — 32 reference px, how every text was sized until now — so every
  saved project opens exactly as it looks. The Size a legacy text *shows* is the one its
  letters have (`textSizeOf`); moving the ruler makes it explicit at that value, no jump.
- **The style grows with the letters.** Outline, shadow, background padding and radius, and
  the box's outer padding are all scaled with the size (`TextOverlayLayout.inkScale`), so a
  look keeps its proportions at any size. The wrap width does not (`canvasScale`): that is
  the re-wrap. `renderScale` leaves the layout so every caller had to choose which it meant.
- **Defaults:** new plain text and template text start at Size 120 (`kDefaultTextSize`, about
  what 32 px is on a phone's canvas today); captions at 100 (`kCaptionTextSize`). Templates
  keep their own `scale` on top.
- **Captions get their size from Size, not scale.** A new set: Size 100, scale 1, wrap width
  86% of the frame. A Size change on a caption reaches its set while "Apply to all captions"
  is on. A regeneration keeps the set's Size. A set saved before this — its size was in its
  scale — is converted on load (`migrateLegacyCaptionSize`), exactly, so it reads Size 100.
- **Where:** a Size tab in the text editor, between Font and Animation, and a Size entry on the
  text's menu opening it (`kTextMenuSheetTools`). The editor stays the one styling surface.
  Range 20–300, snapping at the text's default; tap the readout to reset; one undo per drag.
- **Not keyframable.** Size is a style; animating size is what scale keyframes do.

## Tasks

1. Model field, JSON (omitted when null, clamped on read), `TextLook` classification.
2. Geometry: `textSizeOf`, `textInkScale`; layout `inkScale`/`canvasScale`; every consumer
   chooses (painter, rasteriser, glyph layout, preview tile, layer).
3. Captions: build at Size 100; `captionStyleForNewSet` carries Size; legacy migration on
   load; `_setText` broadcasts Size to the set.
4. Defaults: `newText` and `TextTemplate.apply` at `kDefaultTextSize`.
5. UI: the Size tab and menu entry.
6. CLAUDE.md, full verification, one fresh review.

## Review focus

1. A consumer still drawing with the canvas scale where the layout used the ink scale — text
   overflowing its own box at a non-default Size, in the preview or the file.
2. A legacy text's layout changing at all (it must be byte-identical).
3. The width handles and position math on a text at a non-default Size (they are geometry).
4. A caption set migrated on load that moves, re-wraps or changes size by a pixel.
5. Export sharpness and atlas size at Size 300 (the atlas limit and its warning).
